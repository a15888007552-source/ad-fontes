# Museum Atlas｜七馆重点文物施工说明

日期：2026-09-05。用途：交给 Codex 的编辑资料包，不是已部署网站，也不是无审核的数据库补丁。

## 1. 这次交付了什么

河南馆之外，七馆各15项，共105项选目和重写稿。每项包含推荐顺序、检索卡片短句、约110—150字介绍、入选理由、来源和匹配注意事项。成套编钟、组合器物或遗迹按一项计算，不按照片数凑15件。

**80项主要事实已有外部资料支持；25项仍需核实本件展签、补足独立器物资料或确认具体个体。全部105项的当前仓库记录、照片、原件／复制品身份尚未最终绑定。每馆前6项共42项均属于前一类，但也须先完成照片与记录绑定。**

七馆之间是网站内容板块，不意味着它们属于同一个现实机构。顺序为本站编辑推荐，不是官方排名。“重点文物”不等于国家一级文物、禁止出境展品或官方镇馆之宝。

中国国家博物馆子站完全排除；河南馆上一批15项不在本包重做。币种比较资料中个别引用其他博物馆，只支持通用形制和年代，不把对方的藏品收录进本批或替换本站照片。

## 2. 开始前先确认工作版本

在用户实际指定的分支、工作树上操作。读当前代码、馆目、各馆数据和构建脚本，不要强行回退 main，不覆盖用户或其他 Codex 会话的未提交变更。本次参考的跨馆索引为 `modules/museum-atlas/search-index.json`，观察到的文件 SHA 为 `6413ec2315633858e4a72d7c2b8ebf38cef8a07f`；它只是本次查阅快照，不是要求恢复到的版本。

`existing_record_id` 只是根据查阅记录提出的候选。必须以 `(museum_id, id)` 联合匹配，不能全局按 `artifact-001` 等短 ID 覆盖。`related_existing_record_ids` 表示相关旧条目，不表示同件、可覆盖或已经完成匹配。空 ID 必须继续查当前数据，不得编造。

## 3. 先核对象，再核照片，最后应用正文

依次核对规范名称、年代、出土地／墓号、铭文或器形特征、照片展签以及收藏单位。名称相同不能单独证明是同一件；馆内拍到也不等于本院永久收藏。

原件、复制品、拓本、摹本、数字复原分别建档。由原件材料保护复原的冠饰、玉衣，应明确恢复情况，不自动归成纯复制品。照片中的展签、展柜全景和场景复原不得作为“该原件实拍”的替代物。

秦汉馆若原来只有“兵马俑”“王莽币制”“铜权与秦半两”一类主题组合，保留旧主题记录与深链接，再增加／绑定具体器物子条目。不要把整个展柜记录硬改为一件器物。陕西历史博物馆与秦汉馆出现同一实物时，保留一个器物身份，关联不同拍摄场馆／展示记录，不把它计为两件不同收藏。

未匹配到照片的，报告“照片暂缺”；没有授权或明确来源时，不抓取网图冒充实拍，不使用 AI 生成仿古文物图。不要改已有摄影者署名和版权说明。

## 4. 正文与编辑备注严格分离

读者卡片使用 `canonical_title`、`period`、`card_tagline`；详情介绍使用 `intro`，并保留资料依据的入口。`why_selected`、`editorial_notes`、证据状态及本文件属于编辑层，不能拼进读者简介，不能进入普通全文搜索后制造无关命中。

禁止统一加上“中华文明璀璨瑰宝”“穿越千年”“见证辉煌”“历史的温度”等结尾。不为达到字数补编故事、人物对白、固定礼仪动作、曲目、音高、墓主人、馆藏等级或当日展厅号。

明确有资料缺口的25项，先核展签及对应资料，写清采用证据后再放行。不可以只删除“待核”说明，或把“没有搜到”改成“无可争议”。其他80项也不是免审：须完成对象、照片与原件身份核对。

## 5. 检索入口怎么改

搜索框之后直接呈现本馆第一组重点文物，按本包 `curatorial_rank` 推荐前6项。保持清楚的名称、年代和一行看点；标记“重点文物”，不要另加占据整屏的横幅，不必改七馆各自的视觉主题。提供“查看全部重点”入口；15项全部经审核后，该入口才可显示“15项”。未完成的条目不要硬凑到前台。

默认浏览按重点优先，原有普通条目仍保留；可加入“只看重点”。没有审核通过的条目不能仅凭 `is_highlight=true` 混入首屏。首屏和后续列表共用记录，避免在同一个可见列表中重复渲染同件。

用户输入查询后，先满足关键词相关性以及馆别、年代、器类等筛选条件，再在相关结果中使用重点权重；不得强塞不匹配的重点。清空查询恢复本馆默认推荐顺序。无命中保留真实空状态，不拿推荐卡伪装成搜索结果。

别名只加经核实者，如“㝬簋／胡簋”“皇后之玺／皇后玉玺”。原来 `photos[].featured` 若表示封面照片，不得改作“重点文物”开关。

总馆跨馆检索同步新的规范名、别名及重点字段，不能只改分馆。优先走现有索引生成流程；若没有生成器，明确记录维护方式。不要借此重建检索系统、替换框架或改无关模块。

## 6. 发布门槛与数据字段

本包全部 `auto_publish=false` 是安全默认，不是要求永久不上线。Codex完成核对后，在目标项目的审稿字段中写入证据、映射结果及通过状态，再由审核通过的记录驱动展示。

推荐判定关系：`is_highlight=true` 且 `content_review=passed` 且 `record_binding=verified` 且 `object_identity=verified` 才可进入本次重点列表；有图卡片还须 `photo_match=verified`。项目原有同等字段可复用，不必强行使用这里的字段名。

`official_treasure=null` 表示本包未作官方称号认定，不是认定“不属于镇馆之宝”；不得转换为 false。`current_display_status=not_verified` 表示未核当日在展，不能自动显示“正在展出”。`collection_owner=null` 留待资料核实，不能一律填子站标题。

`image_path=null` 不是删除现有图片的命令。若映射到经过核对的原记录，继续复用现有路径及媒体解析器。秦汉馆、陕历博、陕西考古馆使用过外置媒体解析，保留 `resolveMediaUrl`、`resolveAtlasMediaUrl` 等现有机制，不猜拼新的本地地址。

## 7. 验收时逐项做什么

| 验收项 | 通过条件 |
| --- | --- |
| 范围 | 只修改本包七馆及必要的跨馆索引、检索样式／逻辑；国博和河南正文不动。 |
| 记录 | 输出105项匹配表，明确原 ID、新 ID、组合拆分、缺图、待补证；不得把未完成项目计为通过。 |
| 入口 | 桌面和手机进入文物检索能看到重点；通过的记录按推荐顺序展示，未通过记录不出现。 |
| 查询 | 精确名、别名、关键词、筛选交叉、无结果、清空重置均实测；相关性不被置顶规则破坏。 |
| 去重 | 一件文物多图不重复计数；跨馆展示记录不伪装成多件原物。 |
| 身份 | 拓本／原碑、原件／复制品、借展／自藏没有混淆；年代与尺寸不在同名个体间串用。 |
| 图片 | 旧图不丢、外置媒体可用、详情图和展签可打开；补图有来源与权利说明。 |
| 阅读 | 卡片短句不溢出；“重点”有文字标记，不能只用颜色；移动端、键盘、焦点与弹窗返回有效。 |
| 回归 | 原深链接、返回总馆、原收藏列表、非重点条目、用户照片顺序均保留。 |

提交报告至少包含修改文件、105项映射与阻塞清单、实际测试结果和真实截图。只跑静态检查不能声称完成浏览器验收。用户未授权发布时，不擅自合并或部署。
