# 填写说明：作曲家关系谱数据（给 Gemini / Codex）

你要为一位作曲家填写一份 JSON：`composers/<personId>.json`，同时写一份内部定位文件 `europa-anchors/<personId>.jsonl`。格式以 `SPEC.md` 为准，样例见 `mach.example.json`。全部用简体中文；原文名、作品原题、术语照原文拉丁字母。

## 一、你会拿到什么
- 作曲家的 `personId`、中文名、原文名。
- 要用的书：`books.json` 里的 `bookId` 清单，以及每本书的扫描件或文本（由用户提供）。
- 只用给你的材料。没给的书不要引用，不要凭记忆写任何书的页码。

## 二、页码铁律（最重要）
教科书（格劳特 Grout 等）和词典（新格罗夫 New Grove）是两种书，分开写：教科书填**章节 + 页码**（`refType: "textbook"`），词典填**卷号 + 词条标题**（`refType: "dictionary"`）。下面的页码规则针对教科书；词典条目的 `volume`、`headword` 同样必须照书原样，并同样附一句原话。

1. **`page` 只写书页上印出来的页码**（页眉或页脚的那个数字）。不是 PDF 阅读器显示的第几页，不是图片文件名里的编号，不是你推算出来的数字。
2. 每写一个 `page`，必须在内部文件里写一行定位：同一页上能证明这条信息的**一句原话，逐字照抄**（`quote`），连同 `bookId`、`page`、`anchorId`。找不到这样一句话，就不写这条页码。
3. 页上看不到印刷页码（插图页、空白页、图版）：不写页码，在交付报告里列出。
4. 跨页内容写成 `"151–152"`；罗马数字照印，如 `"xiv"`。
5. 你写的页码和词典条目一律 `"verified": false`（页面显示"未核"）。只有用户翻书核对后才改成 `true`，你永远不要写 `true`。
6. 不同版本、不同译本是不同的 `bookId`，页码不能互相套用。

## 三、电子书与版权铁律
- 电子书、扫描件、PDF、截图**一律不进任何仓库**，也不要上传到任何网站。
- 公开文件里**不写**本机路径（如 `D:\...`）、文件名、扫描件页序号。扫描件页序号只写进内部文件的 `scanIndex`。
- 定位原话只写进内部文件，每条一句，不要整段抄书。
- 内部文件夹不放进 ad-fontes 仓库。

## 四、各节怎么填
**chronology 大事记**：只收书里写明的事件。年份照抄，"约""或""前后"等程度词保留；不要把"次年""晚年"换算成具体年份。每条至少一个 `refs`。

**lineage 谱系**：`category` 只能是 师承、影响、接续、知交、亲缘、对立、比较、待核 八类之一。书里只说"或曾""可能"的师生关系，归 `待核`，不归 `师承`。`evidence` 照四级定：书里有直接史料证据 → `documented`；作者明确断言 → `strongly-supported`；后世史学叙述 → `historiographical`；只是研究者并置比较 → `comparative`。对方在年鉴里就填 personId，不在就填 `targetName`。

**works 作品与乐谱**：作品必须是**本人创作**的（演出、指挥、改编他人的不算）。乐谱链接只收网站页面上明确写着 Public Domain 的版本，`rightsText` 照抄页面原文；页面没写权利信息就不收。链接给网页，不给 PDF 直链，不下载乐谱。

**scholarship 期刊题录**：检索条件写进 `query`（检索词、来源类别、学科、排序、总数、日期）。题录照知网页面抄：题名、作者、单位、刊名、年、期、来源类别、被引。不存摘要、不存链接。`scholars` 只从你抄到的题录里汇总，不另外找人。遇到验证码或登录失效就停下报告，不要绕过。注意同名陷阱（例如检索词同时是别的领域名人），在报告里说明。

**bookRefs**：见第二节。教科书条目填 `chapter` + `page`；词典条目填 `volume` + `headword`，不要混写。

## 五、禁止
- 不准用自己的知识补任何事实、年份、作品名、页码、学者。
- 不准改写书里的确定程度，不加"伟大""划时代"之类的评价词。
- 看不清、拿不准的：留空，写进报告。

## 六、交付
1. `composers/<personId>.json`（UTF-8，合法 JSON，`status` 为 `draft`）。
2. `europa-anchors/<personId>.jsonl`（每个 `anchorId` 一行）。
3. 一份报告：各节条数；没找到页码的条目；看不清的页；同名陷阱；每本书用了哪些页。
交付前自查：公开文件里每个 `anchorId` 在内部文件里都有对应行；每个 `refs` 都能在 `bookRefs` 里找到；没有任何本机路径和 PDF 文件名。
